# Tear pitfalls

Things that went wrong, or nearly did, and the rule that came out of each. Every rule
names the check that enforces it. A rule with no automated guard says so; add one when it
is cheap. [AGENTS.md](../AGENTS.md) "Known traps" keeps the short how-to for each.

Add a row when an incident costs real time. Change a row in place when its guard changes.

| What happened | Cause | Rule | Guard |
| --- | --- | --- | --- |
| `pnpm deploy --help` runs a full build and Wrangler dry run instead of printing help. | pnpm 11 ignores `--help` after a script name and runs the script. | Read `package.json`, never pass `--help` to a script. No package script may publish: `deploy` is a dry run. | `tests/unit/pitfall-guards.test.mjs` (no script runs `wrangler deploy` without `--dry-run`; `deploy` resolves to `deploy:dry-run`) |
| Images and archives written through PowerShell 5.1 redirection come out corrupt. | `>` and pipes re-encode a native program's output as text. | Let the tool write the file itself (`--outFile`, Playwright's `path`, `tar -f`) or use Bash. | None: a shell behaviour, not repository content. The screenshot recipe in AGENTS.md writes through Playwright. |
| Every pull request that touched tutorial code rewrote the same line of `tutorial-gold-binding.json`, so two of them always conflicted and each needed a refresh, even when the tutorial behaved the same (fixed 2026-11-16). | The binding held a committed hash of the tutorial source. | The binding now holds only the gold output's content hash. Staleness is proven by regenerating the gold and comparing it with the committed files; the source hash only keys a local, uncommitted record of that pass. When a build reports "Tutorial gold references are stale", the gold output really changed: regenerate with `TEAR_TUTORIAL_GOLD_WRITE=1` and commit the corpus, proof and binding together. | `tests/unit/tutorial-production-ghost.test.ts` (regenerates and compares); `assertTutorialGoldFresh()` in every build; `tests/tutorial-gold-fingerprint.test.mjs` (two branches changing different tutorial roots merge cleanly) |
| A recursive delete of a worktree could destroy another checkout. | Older worktrees use a `node_modules` junction into another worktree or the canonical checkout; recursive deletes follow it. | Remove the junction alone (`cmd /c rmdir <path>\node_modules`) before the worktree. | `pnpm who` flags `node_modules-link` (read-only; `tests/unit/who.test.mjs`). |
| Plain `pnpm dev` can answer on 5174 from a different worktree than you think. | Plain `pnpm dev` moves to the next free port when 5173 is busy. | Use the launch configurations, which fail instead of moving. | `tests/unit/pitfall-guards.test.mjs` (every `.claude/launch.json` server passes `--strictPort`) |
| Commits during `git rebase` are refused half-way. | HEAD is detached during a rebase and the commit guard refuses detached commits. | Abort the rebase and run `git merge origin/main` on the checked-out branch. | The shared `prepare-commit-msg`/`pre-commit` hooks (outside the repository). |
| 179 commits of finished work existed only on one machine for about ten weeks; production fell behind `main`'s intent without anything failing (found 2026-11-11). | Work was never pushed and no pull request was opened. | Push your `codex/<scope>` branch and open a pull request as soon as it holds reviewable work. | `pnpm who` flags `no-pr` for a branch with commits ahead of `main` and no open pull request; nothing blocks it. |
| 43 worktrees and 62 local branches had piled up; 12 worktrees held uncommitted work (2026-11-11). | Worktrees were not removed after merge, and nothing listed their state. | Remove your worktree and branch after the merge, after checking for uncommitted work and junctions. | `pnpm who` flags `stale`, `dirty` and `merged-or-empty` worktrees; removal stays manual. |
| Lint crashed and 38 of 2,855 unit tests failed on the unpublished line, about 25 of them stale (2026-11-11). | Gates were not run on the line while it grew, so stale tests accumulated unnoticed. | Run the gates the change needs before handing off; CI's required check runs on every pull request. | `pnpm check:functional`, the required CI check. |
| Status in plans went stale the moment work merged: the release-readiness phase table still read "planned" after pull request 85. | Status was written by hand in several documents. | Status lives only in `config/position.json`; `docs/POSITION.md` is rendered from it. | `pnpm check:docs` (stale or hand-edited render) |
| A commit made with `--no-verify` would skip the `pre-commit` and `commit-msg` guards. | Git lets the caller skip `pre-commit` and `commit-msg`. | Never use `--no-verify` or another way around the hooks. | `prepare-commit-msg` still runs under `--no-verify`; the pre-push audit checks every new commit. `tests/unit/pitfall-guards.test.mjs` fails if a script or workflow passes `--no-verify`. |
