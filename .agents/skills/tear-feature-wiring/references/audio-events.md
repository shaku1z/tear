# Sound and music

Read [docs/TEAR_SCORE_INTEGRATION.md](../../../../docs/TEAR_SCORE_INTEGRATION.md) first. In short: music
is recorded stems, authored in the separate music repository and published into this one; the game plays
them with its own Web Audio player. There is no vendored music engine.

- Gameplay and application code publish a semantic sound or music intent. The audio layer (`src/audio/`)
  routes it through the mixer and the music director to the backend.
- Which song plays for a biome, boss or scene is a routing rule in `public/audio/music.json`, generated by
  the music repository. Never edit it or the cue folders by hand, and a game task does not authorize
  touching the music repository.
- Only the audio backend creates an `AudioContext` or connects to the output.
- Keep the Master, Music, SFX and Interface levels and the temporary mute reasons intact.
- Music never blocks the first frame: heavy audio code stays off the startup path.
- An audio preference that is saved follows the saved-field route in
  [data-and-platform.md](data-and-platform.md).

Checks: the audio unit tests, `pnpm check:music` for shipped cues, and `pnpm test:browser:audio` on a test
build for lifecycle and routing.
